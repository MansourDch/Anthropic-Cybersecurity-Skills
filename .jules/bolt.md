## 2023-10-25 - Avoid manual string parsing micro-optimizations over regex
**Learning:** In Python, replacing `re.match` with manual string parsing loops (`for c in key:` with `c.isalnum()`) for frontmatter parsing is a detrimental micro-optimization. It introduces interpreter/bytecode overhead that is typically slower than the C-optimized regular expression engine. Furthermore, Python automatically caches compiled regex patterns, meaning inline `re.match` calls are already highly optimized and module-level `re.compile` yields virtually zero measurable impact.
**Action:** Do not sacrifice code readability by replacing clean regexes with complex nested string logic, especially without a verified bottleneck. Focus on algorithmic inefficiencies (like O(N^2) list copying) rather than micro-optimizing cached regular expressions.
## 2023-10-25 - Avoid O(N^2) list copying inside loop
**Learning:** In parsing loops that progressively build a list (e.g., extracting YAML array items), repeatedly calling `list(list_values)` to assign a copy of the list into a dictionary on every iteration causes O(N^2) performance degradation.
**Action:** When the local list reference `list_values` is subsequently rebound (`list_values = []`) rather than mutated in place or `.clear()`'d, it is perfectly safe to assign the direct reference `data[key] = list_values` without incurring the `list()` copy overhead.
